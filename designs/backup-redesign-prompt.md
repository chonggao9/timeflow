## 角色

你是资深 React Native（Expo）工程师，熟悉本地加密、WebDAV 和移动端状态管理。请在不破坏现有用户数据的前提下，重构本项目的备份模块，并改造「我的」页的备份交互。

## 项目背景（请先阅读，不要凭空假设）

项目路径：`d:\work\timeflow`。先完整阅读以下文件，再动手：

- `src/backup/schema.js`：收集 records / trips / focusSessions / 用户偏好，已排除高德 API Key
- `src/backup/crypto.js`：PBKDF2-SHA256（当前 15,000 次）+ AES-256-CBC + HMAC-SHA256（Encrypt-then-MAC）
- `src/backup/backup.js`：本地沙盒 `/timeflow-backups/`，保留最近 5 份
- `src/backup/webdav.js`：远端固定单文件 `timeflow-backup-latest.json` 覆盖写入，应用密码存 SecureStore
- `src/backup/schedule.js`：自动备份节流 30 分钟 + 模块级防重入锁，`runBackupIfDue` 在 App 启动、打卡保存时调用
- `src/screens/ProfileScreen.js`：「我的」页，约 180–450 行为备份相关 UI

**第一步只读代码，输出「改动计划」，经我确认后再改。**

## 现存问题

1. 云端单文件覆盖：换机或空库备份会抹掉远端历史，无法回退。
2. 恢复前看不到备份内容，且只支持合并，不支持整库覆盖。
3. 自动备份失败被静默吞掉，用户不知道原因。
4. 本地历史快照没有界面可以浏览或恢复。
5. 「我的」页有 5 个备份相关入口，职责重叠，横幅状态是静态文案。

## 硬性约束

- **向后兼容**：必须能读取旧格式（无文件头、PBKDF2 固定 15,000 次的 `timeflow-backup-latest.json` 和本地旧文件）。新旧格式用 `v` 字段区分，缺失即视为 legacy。
- 备份包中**不得包含**高德 API Key、WebDAV 账号密码等凭证。
- 不新增重型依赖；加密继续使用项目现有库。
- 所有用户可见文案使用中文，沿用现有 i18n 机制（若有）。
- 任何会删除或覆盖用户数据的操作，执行前必须先生成本地「恢复前快照」。

## 一、备份逻辑改造

### 1. 统一流水线

```
触发 → 收集数据 → 计算内容哈希 → 与上次成功备份相同？跳过
     → 加密打包 → 逐个写入目标（本地、WebDAV）→ 清理旧版本 → 更新 backupState
```

抽象 `Target` 接口，本地与 WebDAV 各实现一份，调度、加密、保留策略只写一遍：

```js
// src/backup/targets/Target.js
// put(name, bytesOrString): Promise<void>
// list(): Promise<Array<{ name, size, modifiedAt }>>
// get(name): Promise<string>
// remove(name): Promise<void>
```

### 2. 新文件格式（`.tfb`，JSON）

```json
{
  "v": 1,
  "createdAt": "2026-10-12T18:15:00+08:00",
  "device": "Pixel 7",
  "counts": { "records": 1248, "focus": 36, "trips": 210 },
  "hash": "<明文内容 SHA-256>",
  "kdf": { "alg": "PBKDF2-SHA256", "iter": 200000, "salt": "<base64>" },
  "iv": "<base64>",
  "ciphertext": "<base64>",
  "mac": "<base64>"
}
```

- 文件头（除 `ciphertext` 外）为明文，使「版本列表」和「恢复预览」**无需密码**即可展示；`counts` 只暴露数量，不暴露内容。
- 解密才需要密码。KDF 参数从文件头读取，新备份迭代次数 ≥ 200,000；legacy 文件按旧参数解密。
- 密文体内含 `schemaVersion`，为后续字段迁移预留。
- MAC 需覆盖文件头关键字段（`v`、`kdf`、`iv`、`counts`）+ 密文，防止头部被篡改。

### 3. 版本保留（只用一条规则）

- 文件名：`timeflow-YYYYMMDD-HHmm.tfb`，WebDAV 放在 `timeflow/` 目录。
- 云端保留最近 **7** 份，本地保留最近 **5** 份；**上传成功后**才清理最旧的，失败不清理。
- 删除 `latest.json` 指针；时间戳最大的即最新版本。
- 首次运行发现旧的 `timeflow-backup-latest.json` 时：保留不动，在版本列表里作为一个 legacy 版本显示，用户成功完成一次新格式备份后再提示是否清理。

### 4. 触发规则

| 触发 | 规则 |
|---|---|
| 数据变化 | 防抖 60 秒，且距上次自动备份 ≥ 30 分钟 |
| App 切后台 | 有未备份的变更时触发一次 |
| 手动点击 | 忽略节流，立即执行 |

保留现有的防重入锁。哈希与上次成功备份一致则跳过，并在手动备份时给出「数据无变化，已是最新」提示。

### 5. 防覆盖保护

自动备份前，若满足「本机记录数 < 最新远端版本记录数 × 50% 且远端 ≥ 10 条」，则**不上传**，将 `backupState.status` 置为 `needConfirm`。用户在界面点「仍然备份」后才继续（本次手动）；点「保持暂停」则维持暂停。

### 6. 恢复流程

1. 选择版本（列表直接来自文件头，云端与本地合并展示，用标签区分）。
2. 输入密码并验证（解密 + MAC 校验）；失败给出「密码不正确」，不泄露更多信息。
3. 选择恢复方式：
   - **合并（默认）**：保留现有数据，补入备份中缺少的记录。
   - **完全覆盖**：以备份为准替换全部数据。
4. 展示「恢复前 → 恢复后」条数对照，确认。
5. **执行前自动保存一份本地恢复前快照**（标记 `snap`，计入本地保留份数之外，最多保留 3 份）。
6. 完成后提供「回退到恢复前」入口。

> ⚠️ 合并逻辑务必先检查记录是否有稳定 `id`、`updatedAt` 和删除标记。若没有删除标记，合并会把用户已删除的记录复活。请在改动计划里说明现状，并给出方案（例如为删除增加 `deletedAt` 墓碑字段，或明确告知「合并只增不删」）。

### 7. 状态对象与错误码

```js
backupState = {
  status: 'ok' | 'stale' | 'failed' | 'needConfirm' | 'notConfigured',
  lastSuccessAt: number | null,
  lastCounts: { records, focus, trips } | null,
  cloud: { enabled: boolean, lastError: null | { code, at } },
  local: { enabled: boolean }
}
```

- `stale`：距上次成功备份超过 3 天（由读取时计算，不落盘）。
- 错误码只分四类：`AUTH`（401/403）、`NETWORK`（超时/离线）、`QUOTA`（507/空间不足）、`UNKNOWN`。每类对应一句中文文案和一个操作。
- 状态持久化（AsyncStorage），UI 通过订阅或 hook（如 `useBackupState`）读取，不在组件里各自推导。

## 二、UI 改造（参照设计稿 `timeflow-backup-ui.html`）

### 1. 「我的」页

- 移除「立即备份 / 从备份恢复 / 同步与安全设置 / 导出数据 / 清空所有打卡记录」以及顶部静态「云端自动保护中」横幅。
- 在用户卡片下方放**一张备份状态卡**，点击进入「备份与恢复」二级页：

| status | 颜色 | 标题 | 副文案 | 右侧 |
|---|---|---|---|---|
| ok | 绿 | 备份与恢复 | 上次备份 10 分钟前 · 1,248 条打卡 / 云端 + 本地 · 已加密 | › |
| stale | 黄 | 已 3 天未备份 | 上次备份 10-09 21:10 | 「立即备份」按钮 |
| failed | 红 | 云端备份失败 | 授权已过期，本地备份正常 | 「去修复」按钮 |
| needConfirm | 黄 | 自动备份已暂停 | 记录数明显减少（1,248 → 312） | 「查看」按钮 |
| notConfigured | 灰 | 尚未开启备份 | 设置备份密码，保护你的打卡数据 | 「去设置」按钮 |

- 其余设置重新分组：**通用**（语言、主题）、**打卡**（一键打卡 + 今日状态、位置调试）、**关于**（检查更新、隐私协议）。
- 修正副标题错字：「个人信息与保好」→「个人信息与偏好」。
- 列表图标统一为同一暖色系，仅危险项使用红色；右侧辅助文字提高对比度（≥ 4.5:1）。
- 底部 Tab 增加文字标签；滚动内容增加底部内边距，避免被 Tab 栏遮挡。
- 去掉「零泄露风险」这类绝对化表述，统一为「已加密」「端到端加密」。

### 2. 「备份与恢复」二级页（新）

自上而下：

1. **状态头**：状态图标 + 标题 + 副文案；下方三枚状态标签（云端 / 本地 / 加密）。
2. **状态横幅**（仅异常状态）：failed → 含「去修复」；needConfirm → 含「保持暂停 / 仍然备份」；stale → 提示性文案。
3. **主按钮**「立即备份」：执行中显示进度条和「正在加密并上传…」；手动备份失败时在页内显示具体原因，而不是弹窗。
4. **历史版本**：云端 + 本地合并列表，每行显示时间、设备、打卡数和来源标签（云端 / 本地 / 快照）；点击进入恢复流程。
5. **设置**：云端同步（WebDAV）、备份密码、自动备份开关、导出可读数据（标注「未加密」徽标）。
6. **危险操作**（最底部）：清空所有打卡记录。

### 3. 恢复流程（底部弹层，4 步）

验证密码 → 选择方式（合并 / 覆盖，覆盖用红色并写明将删除多少条）→ 确认（恢复前 / 恢复后条数对照 + 「将先保存恢复前快照」提示）→ 进度 → 完成（含「回退到恢复前」）。

### 4. 首次设置（2 步）

1. 设置备份密码（两次输入 + 强度条 + 「忘记密码无法找回」醒目提示）。
2. 可选 WebDAV（地址、账号、应用密码，「测试连接」通过后才可点完成）；提供「跳过，仅本地备份」。

### 5. 清空确认

居中弹窗，说明后果，要求输入「清空」才可点击；确认后先写入快照再清空，并提示「已清空，恢复前快照已保存」。

### 6. 失败提示原则

- 单次自动备份失败：只改变状态卡颜色和文案，不弹窗。
- 连续 2 次失败：下次打开 App 时提示一次，带「去修复」。
- 手动备份失败：页内显示具体原因与重试。

## 三、分阶段交付（每阶段单独提交，可独立回滚）

**阶段 1：数据安全**
`Target` 抽象、新文件格式（含 legacy 读取）、多版本保留、哈希跳过、防覆盖保护、`backupState` 与错误码映射。

**阶段 2：恢复与可见性**
恢复流程（预览、合并/覆盖、恢复前快照、回退）、失败状态记录、备份与恢复二级页、「我的」页状态卡。

**阶段 3：收尾**
首次设置流程、云端设置页修复流程、清空确认、本地快照管理、文案与样式细节。

## 四、验收清单

- [ ] 旧版 `timeflow-backup-latest.json` 与旧本地备份可被新版本读取并恢复
- [ ] 连续备份只在数据变化时生成新版本；云端 ≤ 7 份、本地 ≤ 5 份
- [ ] 本机记录数骤减时不会自动覆盖云端，状态为 `needConfirm`
- [ ] 上传失败时不清理旧版本；失败原因落到 `backupState.cloud.lastError`
- [ ] 版本列表与恢复预览无需输入密码；解密必须输入正确密码
- [ ] 错误密码、被篡改的文件（MAC 不通过）、损坏的 JSON 都有明确提示，不崩溃
- [ ] 合并模式不会复活已删除记录（或已明确告知「只增不删」）
- [ ] 覆盖恢复与清空记录之前都会生成快照，且「回退」可用
- [ ] 备份包与日志中不含高德 Key、WebDAV 密码
- [ ] 「我的」页五种状态的卡片展示与跳转符合上表
- [ ] 弱网 / 离线 / 授权过期 / 空间不足 四类错误各有对应文案
