# 番茄专注功能需求说明(React Native)

Oct 10, 2026 · @Chase Li

## 概述与范围

这次改动把番茄专注页从“填表式”改成“番茄会成熟”的体验，并给每次专注加上必选分类，让洞察页能按分类统计。

**范围内**

- 首页「室内专注」的三个状态：待开始、专注中、收获。
- 洞察页的「专注」标签：时间筛选、概览、趋势、分类分布、习惯。
- 专注记录新增分类字段。

**范围外**

- 「行程轨迹」模式、「历史」标签、「查看记录」页、「分类说明」页，沿用现有实现。

**必须保留的现有元素**：顶部模式切换、「今日专注」卡片、分类网格、任务输入框、预设时长和「自定义」、背景声音、底部导航。

**参考原型**：设计画布「番茄专注设计」。交互以「番茄会成熟 · 可玩原型」为准，其余画板是静态参考。原型里没有震动、提示音、真实的背景声音和后台计时，这些见「实现建议」和「待定事项」。

## 专注分类

共 6 个分类，每次专注必须选一个；没有“其他”，归不进去的事放「生活」。归类看目的，不看动作。

| 分类 | 存储 key | 颜色 | 包含 | 归类规则 |
| --- | --- | --- | --- | --- |
| 工作 | work | #3A62D8 | 写代码、会议、邮件、客户沟通、接单 | 为职场或收入做的事 |
| 学习 | study | #D33A3A | 备考、课业、阅读、网课、学新技能 | 为了输入知识的事 |
| 创作 | create | #E8891B | 写作、设计、剪辑、个人项目、爱好 | 为了产出自己的东西 |
| 身心 | wellbeing | #2E9A6B | 冥想、锻炼、休整 | 照顾身体和状态的事 |
| 生活 | life | #1F90B0 | 家务、整理、行政杂事 | 维护日常运转的事，也是兜底 |
| 规划复盘 | review | #7B55C4 | 计划、复盘、拆目标 | 管理自己和时间的事 |

颜色值是我从现有截图里估的，实现时以现有代码里的值为准。“未分类”用灰色 #B8AFA8，只用于旧记录的显示，不出现在选择网格里。

## 数据模型

专注记录新增一个必填的分类字段，旧记录不迁移，统计时统一归入“未分类”。

**字段**

| 字段 | 状态 | 说明 |
| --- | --- | --- |
| category | 新增，必填 | 取值见「专注分类」表的存储 key；旧记录为空 |
| goalName | 沿用 | 任务名，选填；为空时不再显示“未命名专注”作为分类 |
| 开始时间 | 需确认 | “黄金时段”需要。现有记录若没有，先不做这一项 |
| 完成状态 | 需确认 | “完成率”“中途放弃”需要。现有记录若没有，这两项先不做 |

我不清楚现有记录的完整字段，表里标“需确认”的两行请开发对照现有表结构判断。

**统计口径**（这是最容易出错的地方，请所有展示位置共用同一个计算函数）

| 指标 | 口径 |
| --- | --- |
| 专注时长 | 筛选范围内已完成记录的时长之和，单位分钟。没有完成的记录不计入 |
| 番茄数 | 筛选范围内已完成记录的条数 |
| 日均 | 总时长 ÷ 范围内已过的天数（含今天）。“全部”从第一条记录那天算起 |
| 较上期 | 和上一个同长度周期比；上期为 0 时不显示百分比 |
| 完成率 | 完成数 ÷ 开始数 |
| 分类占比 | 分类时长 ÷ 总时长，按时长从大到小排；没有记录的分类不显示。四舍五入后合计不到 100% 可以接受 |
| 今日专注卡片 | 次数 = 今天已完成条数；时长 = 今天总时长；进度条 = 各分类时长占比，按时长从大到小排 |

现有洞察页的“总时长 26m、日均 27m”这类自相矛盾，来自各个展示位置各自取整。要求：总时长先按秒或分钟整数算出来，再统一格式化，分类时长之和必须等于总时长。

## 页面一：待开始

从上到下共 9 个区块。番茄区域占满除其他区块之外的全部空间，最小高度 200，不要写死尺寸。

| 区块 | 内容 | 规格与交互 |
| --- | --- | --- |
| 1 顶部 | 标题「今天」、日期；右侧「行程轨迹 / 室内专注」切换 | 切换按钮高 44，当前项白底红字加粗 |
| 2 今日专注卡片 | 一行：「今日专注」、红色的「3 次 · 3小时3分」、「查看记录 ›」 | 卡片高 48，底边贴一条 6 高的分类进度条。「查看记录」点击区域高 44，跳到现有记录页 |
| 3 分类 | 标题「这次专注做什么？」，右侧红字「分类说明」；3×2 网格 | 按钮高 44，间距 8。选中 = 主色描边 + 浅红底 + 加粗，单选。默认沟用上次选择；首次使用默认选中「学习」 |
| 4 任务输入 | 单行输入框，占位「选填，例如：写周报」 | 高 48。字数上限待定，建议 30 字 |
| 5 番茄 | 大番茄，番茄上写分钟数 | 上下拖动调时长：每拖 10 像素变 5 分钟，范围 5–90 分钟。时长越长番茄越大（缩放 0.8 到 1.0）。番茄颜色固定为青色 #8DB255 |
| 6 预设时长 | 15 / 25 / 45 / 60 和「自定义」 | 按钮高 44，选中态同分类。「自定义」平时是虚线框；拖到非预设值时变成「35 分」这样的选中态 |
| 7 背景声音 | 一行：「背景声音」、当前选项、箭头 | 高 48，点击进入现有的声音选择。原型里点一下是循环切换，仅演示 |
| 8 开始按钮 | 「按住开始专注 · N 分钟」 | 高 56，胶囊形。见下方「按住开始」 |
| 9 底部导航 | 打卡 / 洞察 / 我的 | 不变，高 64 |

**按住开始**

- 按住按钮 900 毫秒，按钮左到右被深红 #8E2A20 填满，填满后进入「专注中」。
- 按住过程中文案变成「继续按住…」。
- 提前松手：进度清零，文案显示「再按住一会儿哦」1.5 秒后恢复。
- 分类始终有一个选中项（首次使用默认「学习」，之后沿用上次选择），所以开始按钮不需要置灰。这和原型一致。
- 无障碍：必须提供不需要长按的替代操作（见「实现建议」）。

## 页面二：专注中

专注中隐藏全部干扰元素，只留番茄、倒计时和两个控制按钮。番茄随进度从青涩长到成熟，用户看颜色就能知道进度。

**隐藏**：模式切换、今日专注卡片、分类网格、任务输入、预设时长、底部导航。

**显示**

- 顶部：「今天第 N 次」，下面是分类胶囊（色点 + 分类名，有任务名则接在后面）。第 N 次 = 今日已完成次数 + 1。
- 中部：番茄。
- 下部：倒计时（68，等宽数字）、阶段文案、暂停和放弃按钮、背景声音一行（可切换）。

**番茄成熟的变化**（p = 已用时间 ÷ 总时长，范围 0 到 1）

| 元素 | 变化 |
| --- | --- |
| 番茄大小 | 缩放从 0.55 线性到 1.0 |
| 番茄颜色 | p 在0–0.5：青 #8DB255 到橙黄 #E9A23B；p 在0.5–1：橙黄到红 #D93A2B，均为 RGB 线性插值 |
| 页面背景 | #EEF3E2 线性到 #FBE3D6 |
| 呼吸动画 | 番茄上下浮动 5，周期 3.2 秒循环；暂停时停止 |
| 阶段文案 | p<0.33「青涩的小番茄」；0.33–0.66「正在转红」；0.66–0.9「快熟了」；p≥0.9「马上就能收获了」；暂停时显示「已暂停」 |

系统开启“减弱动效”时，呼吸动画关闭。颜色和大小的变化保留，这是信息，不是装饰。

**控制按钮**

- 暂停 / 继续：主按钮，高 64，点一下切换。暂停时计时停止，总时长不多算。
- 放弃：次按钮，高 56。第一次点击文案变「再点一次放弃」，3 秒内再点才真的放弃，超时恢复。放弃后回到待开始，任务名清空。
- 放弃的记录是否保留用于统计“中途放弃”，见「待定事项」。

## 页面三：收获

倒计时归零时自动进入收获页，用户在这里确认分类并把这颗番茄记入「今日专注」。这是分类最准的时刻，所以改分类要一点就改。

**触发与反馈**

- 到点时触发震动和提示音（原型里没有，需开发实现）。
- 番茄弹出：缩放 0.8 → 1.08 → 1.0，用时 0.5 秒。
- 8 个彩点从番茄中心向四周散开并淡出，用时 0.9 秒，颜色为红 #D93A2B、黄 #E9A23B、绿 #4E8F4A。
- 番茄上显示白色对勾。

**内容**

- 标题「收获一颗番茄」，副标题「今天第 N 次 · 分类 · M 分钟」，有任务名则再显示一行。
- 「分类不对？现在点一下就能改」和一个与首页相同的 3×2 分类网格，默认选中本次的分类。

**按钮**

- 「记入今日专注」（主，高 56）：保存记录并回到首页。首页「今日专注」的次数、时长、进度条立即更新，进度条宽度用 0.5 秒过渡。
- 「记入并休息 5 分钟」（次，高 48）：保存后进入休息。休息页还没有设计，原型里两个按钮效果相同。

**防丢失**：用户没有点按钮就退出 App 时，记录也要自动保存，分类取当前选择。这是我的建议，原型里没有体现。

## 洞察页：专注分析

现有页面的问题是时间范围不一致、分布依赖空标签、数字自相矛盾、图表读不出信息。新版顶部一个时间筛选，下面所有模块跟着它走。

页面顺序：筛选条 → 概览 → 趋势 → 分类分布 → 习惯。越往下越次要。

| 模块 | 内容 | 优先级 |
| --- | --- | --- |
| 时间筛选 | 今天 / 本周 / 本月 / 全部，单选，默认本周。按钮高 44 | P1 |
| 概览 | 3 张卡：专注时长（下方小字较上期变化）、番茄数（下方小字完成率）、日均（下方小字写明“按已过 N 天”） | P1，口径见「数据模型」 |
| 分类分布 | 每类一行：色点 + 分类名 + 番茄数 + 时长 + 占比 + 占比条。点一行展开，显示该类时长最高的 3–5 个任务名。旧记录归“未分类”灰色显示 | P1 |
| 趋势图 | 本周按天 7 根柱，本月按天，全部按周。每根柱下写日期，今天高亮，柱顶写分钟数。没有专注的日子画一个空心小圆点，不留空白 | P2 |
| 专注习惯 | 黄金时段（上午 6–12、下午 12–18、晚上 18–23、深夜 23–6 的时长条，最多的高亮）、平均每个番茄时长、中途放弃次数、一句自动总结 | P3，依赖“开始时间”和“完成状态”字段 |
| 空状态 | 所选范围没有记录时，概览显示 0 和破折号，下方放一张引导卡：“今天还没有专注记录”、六个分类标签、「开始专注」按钮，和一句“想看以前的数据？切换到「本周」或「全部」” | P1 |

一句自动总结的模板：“本周你在 {时长最高的分类} 上花了 {时长}，大多集中在 {黄金时段}。”记录少于 3 条时不显示。

设计画布里的「分析页 · 有数据」和「分析页 · 空状态」是这一页的静态参考。画板里的数字是演示用的假数据。

## React Native 实现建议

关键原则有三条：计时用时间戳、动画跑在 UI 线程、状态用状态机。下面的库名是建议，以项目已有依赖和版本为准。

**状态机**

首页用一个状态变量表示当前阶段：`idle`（待开始）、`holding`（按住中）、`running`、`paused`、`done`。用 `useReducer` 或 zustand 的状态机，不要用多个布尔值组合。转移规则见下面的流转图。

&#91;embedded content: 首页状态流转 · 5 个状态\]

专注中和暂停中都可以放弃，放弃和提前松手都回到待开始；只有倒计时归零才进入收获。

**推荐库与用途**

| 需求 | 建议 |
| --- | --- |
| 拖动调时长 | react-native-gesture-handler 的 Pan 手势。在 reanimated 的 worklet 里算：分钟数 = 起始值 + 取整(−translationY ÷ 10) × 5，限制在 5–90。如果首页可滚动，给手势设 activeOffsetY 避免和滚动冲突 |
| 按住开始 | 用 Gesture.LongPress 或 Pressable 的 onPressIn / onPressOut，配合 reanimated 的 withTiming 把填充宽度从 0 到 100% 跑 900 毫秒，松手时 cancelAnimation 并重置 |
| 番茄绘制 | react-native-svg（Ellipse、Path）。缩放用 useAnimatedStyle 的 transform |
| 颜色渐变 | reanimated 的 interpolateColor，取值区间 \[0, 0.5, 1\]，番茄和页面背景各一组 |
| 呼吸动画 | withRepeat + withSequence。用 useReducedMotion 判断系统设置，开启时不跑 |
| 彩点散开 | 8 个 Animated.View，各自跑 translate 和 opacity。若设计后续要更复杂的特效，再考虑 Lottie |
| 震动反馈 | 拖动跨过每 5 分钟一档的轻震、收获时一次重震。expo-haptics 或 react-native-haptic-feedback |
| 背景声音 | 需要锁屏后继续播放，用 react-native-track-player 这类支持后台播放的库 |
| 到点提醒 | 本地通知（notifee 或 expo-notifications），开始时按结束时间排一条，暂停或放弃时取消，恢复时重排 |

**计时**

- 记录开始时间戳和累计暂停时长，剩余时间 = 总时长 − (当前时间 − 开始时间 − 累计暂停)。不要每秒累加一个计数器，App 进后台后它会停。
- setInterval 只负责每 100–250 毫秒刷新显示。
- 监听 AppState，从后台回到前台时重新计算；如果已经超时，直接进入收获页。
- 进程被系统杀掉后重新打开 App，要能根据已保存的开始时间恢复专注中或收获页。所以开始时就要把分类、任务名、时长、开始时间写入本地存储。

**性能**

- 倒计时文字拆成独立组件，每次刷新只重渲染它。
- 番茄的缩放和颜色用 shared value 驱动，不要每次计时刷新都走整个页面的 setState。

**无障碍**

- 分类按钮设 accessibilityRole="radio"，accessibilityState 的 selected 和当前选中一致。
- 「按住开始」按钮用 accessibilityActions 提供一个“开始专注”动作，让 TalkBack 和 VoiceOver 用户不用长按。
- 拖动调时长也要有替代：预设按钮不需要手势，已经满足。
- 所有动画尊重系统“减弱动效”。

## 验收标准与待定事项

**验收清单**

- [ ] 首次使用默认选中「学习」，之后默认沿用上次选择
- [ ] 按住约 900 毫秒开始；提前松手进度清零并提示
- [ ] 拖动调时长范围 5–90、步长 5；预设和“自定义”的高亮跟当前时长一致
- [ ] 专注中退到后台 10 分钟再回来，剩余时间正确
- [ ] 暂停后继续，总时长不多算、不少算
- [ ] 放弃需要二次确认，3 秒后自动恢复
- [ ] 专注中杀掉 App 再打开，能恢复到正确状态
- [ ] 倒计时结束进入收获页；改过分类后，保存的是改后的分类
- [ ] 记入后，首页「今日专注」的次数、时长、进度条和记录一致
