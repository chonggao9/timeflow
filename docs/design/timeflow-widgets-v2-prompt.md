## 数据安全底线（优先级高于其他所有要求）

1. **不改变现有记录的数据结构。** 打卡 / 行程 / 专注记录的表结构、字段名、`id` 一律保持原样。
2. **小组件不保存自己的数据。** 读写与 App 同一份本地数据，状态以 App 内为准；不要在小组件侧另建一份"副本"。
3. **打卡走同一个函数。** 小组件里的「打卡」必须复用 App 内「一键打卡」的同一段逻辑，不要另写一套写入代码。
4. **凭证不进小组件。** 高德 Key 等一律不写进小组件配置、共享存储明文或日志。
5. 删除旧小组件时，**不得删除或迁移任何用户已有的打卡、行程、专注记录**。旧小组件如果有自己的存储（如 SharedPreferences），先在计划里说明里面有什么，清理前问我。
6. 如果某一步可能让真实数据丢失或被覆盖，请停下来问我，不要自行决定。

## 设计原则

- 小组件是「快捷入口」，不是第二个 App：一眼看懂状态，点一下完成一个动作。
- **不耗电：禁止每秒刷新。** 只在用户操作、状态变化、整分钟（番茄运行中）时刷新。
- **点击先反馈。** 打卡点击后立即出现「已打卡 hh:mm」，不要等待落盘才有变化。
- **失败要说清楚。** 没有定位权限、读取失败、没有今日行程时，显示原因和一个可点的出口，不要静默没反应。
- 点击组件空白区域打开 App 对应页面（番茄 → 专注页，行程 → 打卡页）。
- 全局文案中文口语化，不使用绝对化表述；组件里不使用 emoji，图标用矢量。
- 所有可点击区域不小于 44dp；白字按钮底色满足 4.5:1 对比度。

## 二、新方案

### 1. 技术方案（在计划里对比并等我确认）

- **方案 A（推荐先评估）：** `react-native-android-widget` + Expo config plugin。用 JSX 描述组件，圆环、番茄、地图用 SVG 绘制，点击由后台任务处理。需要说明：是否必须 prebuild / Dev Client（不能在 Expo Go 里运行）、对包体和构建的影响、后台任务读写本地数据是否可行。
- **方案 B：** 自写 Kotlin 原生 widget + Expo module / config plugin。可以用原生 `Chronometer` 和 `AlarmManager`，但维护成本高。
- 无论哪种，说明各尺寸如何声明（4×2 / 4×1 / 2×2）、如何跟随主题。
- 只做 Android；iOS 不在本次范围，除非计划阶段我另行说明。

**番茄专注**

|---|---|
| 1 | 4×2 完整版（圆环 + 模式 chip + 标题 + 开始/暂停 + 重置）、2×2 圆环 |
| 2 | 4×1 迷你条、深色主题 |
| 3 | 2×2 番茄、2×2 深色大数字、2×2 今日统计 |

### 3. 状态与数据

番茄专注，只保留一个小状态对象并持久化，App 和小组件共用：

```js
pomodoroState = {
  mode: 'focus' | 'short' | 'long',
  running: false,
  endAt: null | number,        // 运行中：结束时间戳
  remainingMs: 1500000,        // 暂停或未开始时的剩余毫秒
  completedToday: 0,
  updatedAt: 0
}
```

- **用结束时间戳而不是剩余秒数**，应用被杀后可以恢复。
- 时长：专注 25 分钟、短休 5 分钟、长休 15 分钟。
- 倒计时结束必须由系统级的计时（本地通知或 AlarmManager）触发，保证 App 和小组件都能在结束时更新状态，并发一条通知。
- 每 4 个番茄进入长休，否则进入短休；休息结束回到专注，结束后都停在「待开始」。

行程打卡：

- 今日站点来自现有行程数据，不新增字段。
- 状态用「已打卡站点数」推导：已完成 / 当前 / 未到。
- 点击「打卡」：调用与「一键打卡」相同的函数。**Android 10 以后后台定位受限**，请在计划里说明点击时如何拿位置：用最近一次缓存位置并标注，还是拉起 App 完成。不要为此申请后台定位权限，除非我同意。

### 4. 倒计时显示策略（必须在计划里确认）

小组件不做秒级倒计时：

- 运行中显示「剩余 N 分」（向上取整）和「hh:mm 结束」，**每整分钟刷新一次**；圆环、进度条、番茄随之每分钟前进一格。
- 整分钟刷新需要可靠的触发机制，请评估：精确闹钟（Android 12+ 的权限要求）、前台服务、以及电量影响。
- 如果无法做到整分钟刷新，退化为：只在用户操作、模式切换和结束时刷新，运行中只显示「hh:mm 结束」，**不要显示会变旧的剩余时间**。
- UI 稿顶部有「分钟级 / 秒级」开关可以对比两种效果，以「分钟级」为准；秒级只存在于 App 内。

### 6. 交互

**番茄专注**

| 点击 | 行为 |
|---|---|
| 开始 / 暂停 | 切换 `running`，写入 `endAt` 或 `remainingMs`，立即刷新 |
| 重置 | 回到当前模式满时长并停止 |
| 模式 chip | 切换模式，重置时长并停止 |
| 2×2 整卡 | 开始 / 暂停 |
| 空白区域 | 打开 App 专注页 |

状态文案：待开始 / 专注中（休息中）/ 已暂停；按钮文案：开始 / 暂停 / 继续。

**行程打卡**

| 点击 | 行为 |
|---|---|
| 打卡 | 记录当前站点，时间轴推进，副标题短暂显示「已打卡 hh:mm」约 2 秒 |
| 4 站全部完成 | 按钮变「完成」；再点一次回到 App 查看，不在组件里清空数据 |
| 空白区域 | 打开 App 打卡页 |

> UI 稿里「重来」是演示用，真实数据里不要在组件内清空今日行程。

### 7. 错误与空状态

- 今天没有计划行程：「今天还没有计划行程」+「去添加」。
- 没有定位权限：「需要位置权限」+「打开 App」。
- 读取数据失败：显示上次状态 +「点击刷新」。
- 刷新后仍失败：只在组件上显示小字提示，不弹通知。

### 8. 「我的」页「桌面小组件」说明页

- 两个组件的预览卡（直接复用同一套样式），说明每个组件有哪些尺寸。
- 添加步骤：长按桌面空白处 → 小组件 → 找到 TimeFlow → 拖到桌面。
- 部分手机系统需要在设置里允许 TimeFlow 后台运行 / 自启动，否则倒计时结束提醒可能不及时，用一小段提示说明。

## 三、UI 规格（以 `timeflow-widgets-v2-ui.html` 为准）

- 严格按 UI 稿还原配色、圆角、字号、间距和布局，有冲突先问我。
- UI 稿里的持续动画（打卡按钮脉冲、定位雷达扫描、番茄灌满的平滑过渡）在桌面组件里**不实现**，统一用静态外观；只保留点击后的状态切换。
- 圆环、番茄、地图、热力格用 SVG 或 Bitmap 绘制，注意 Bitmap 尺寸限制，按组件实际像素大小生成。
- 每个尺寸使用独立布局，不要用一个布局硬缩放。
