## 设计原则

1. **没有密码，没有加密设置。** 备份是一个可直接阅读的 JSON 文件，用户感知不到加密。
2. **凭证不入备份。** 高德 API Key、WebDAV 地址 / 账号 / 应用密码一律不写进备份文件；WebDAV 应用密码仍存 SecureStore。
3. **任何会覆盖或删除用户数据的操作，执行前先自动备份一份**（恢复、导入覆盖、清空），并且恢复后可以一键撤销。
4. **备份失败不能破坏已有备份。** 先写临时文件并校验，成功后才替换 / 清理旧文件。
5. **诚实提示风险。** 备份默认只在本机，卸载应用或丢失手机会一并消失，界面要主动引导用户「保存到文件」或开启云端副本。

## 二、新备份方案

### 1. 文件格式（`.json`，明文，可读）

```json
{
  "app": "timeflow",
  "v": 1,
  "createdAt": "2026-10-14T10:15:00+08:00",
  "device": "Pixel 7",
  "counts": { "records": 1248, "focus": 36, "trips": 210 },
  "data": {
    "records": [],
    "trips": [],
    "focusSessions": [],
    "prefs": {}
  }
}
```

- 文件名：`timeflow-YYYYMMDD-HHmm.json`。
- `app` 与 `v` 用于导入时校验；缺失或不匹配即判定为「不是 TimeFlow 备份文件」。
- 解析时对每个字段做类型校验，损坏的文件给出友好提示，不能崩溃。
- `v` 为将来字段迁移预留；遇到更高版本时提示「请先更新应用」。

### 2. 存放位置与类型

- 本机：应用私有目录 `documentDirectory/backups/`。
- 每份备份有 `kind`：`auto`（自动）、`manual`（手动）、`safe`（恢复前 / 清空前自动生成）。`kind` 写在本机的索引里（或文件名中），不依赖读取整个文件。
- 备份记录列表需要快速展示：时间、`kind`、条数、文件大小。建议维护一个小的索引文件 `backups/index.json`，丢失时能从目录重建。

### 3. 触发规则

| 触发 | 规则 |
|---|---|
| 自动备份 | 每天最多一次；App 回到前台或切后台时检查，**数据有变化才备份**；总开关默认开 |
| 手动备份 | 用户点「立即备份」，忽略每日限制，但内容无变化时提示「数据没有变化，已是最新」，不生成新文件 |
| 危险操作前 | 恢复、导入覆盖、清空前自动生成 `safe` 备份 |

「内容有变化」用数据内容哈希（项目已有 SHA-256 能力就用，没有就用 `counts` + 最近修改时间）与上一份备份比较。

### 4. 保留策略（一条规则说清）

- 自动备份最多保留 **7 份**，超出后删除最旧的。
- **自动清理时永远保留「记录数最多」的那一份**，防止空库或数据骤减的备份把完整数据挤掉。
- `manual` 和 `safe` 不会被自动清理，用户可手动删除；两者合计最多 10 份，超出时提示用户清理。
- 只有新备份写入并校验成功后，才执行清理。

### 5. 恢复

来源有两种：备份记录里的某一份，或「从文件导入」选择的文件。两者走同一个流程：

1. 先展示备份内容（打卡 / 专注 / 行程条数、创建时间、设备），无需任何密码。
2. 用户选择方式：
   - **回到这个时间点（默认推荐）**：以备份为准整体替换当前数据，并写明「现在多出的 N 条记录会被替换」。
   - **只补回缺少的记录**：保留现有数据，按稳定 `id` 补入缺少的记录，并写明「预计补回 N 条；可能会补回你之后删掉的记录」。
3. 点「恢复」后：先自动生成 `safe` 备份 → 写入数据 → 完成页提供「撤销恢复」（用刚才的 `safe` 备份还原，并移除该条记录）。
4. 恢复操作要在事务或「先写临时数据再切换」的方式下完成，中途失败时当前数据保持原样。

> ⚠️ 合并依赖稳定 `id`。如果现有记录没有 `id`，请在改动计划里说明，并给出方案（例如用「时间 + 位置」组合键），不要擅自改数据结构。

### 6. 保存与导入文件

- **保存备份文件**：生成当前数据的 JSON，通过系统分享面板让用户发给微信 / QQ、存到手机文件或网盘；成功后记录「已保存过文件」状态，用于去掉首页的风险提示。优先使用项目已有的 `expo-sharing` / `expo-file-system`，需要新增依赖时先告诉我。
- **从文件导入备份**：系统文件选择器选 `.json`，校验通过后展示内容，再走上面的恢复流程；无效文件提示「这不是 TimeFlow 备份文件，请重新选择」。
- **导出为表格（CSV）**：保留原有导出能力，放进同一个分组，文案标注可用 Excel 打开。

### 7. 云端副本（可选，WebDAV）

- 默认关闭。开启后，每次本机备份成功就把同一个文件上传到 `timeflow/` 目录，云端保留最近 **3 份**；上传失败不影响本机备份，也不清理云端旧文件。
- 设置页：服务器地址、账号、应用密码、「测试连接」通过后才能开启；可随时关闭。
- 页面文案提示：备份文件未加密，请使用只有自己能访问的空间。
- 本阶段不做「从云端列表恢复」；换机时用户在云端下载文件后用「从文件导入」即可（若希望做，作为后续阶段单独评估）。

### 8. 状态与错误

只保留一个小状态对象并持久化（AsyncStorage），UI 通过 hook（如 `useBackupState`）读取：

```js
backupState = {
  lastSuccessAt, lastCounts,
  lastError: null | { code: 'NO_SPACE' | 'WRITE_FAIL' | 'CLOUD_FAIL', at },
  autoEnabled: true,
  cloudEnabled: false,
  savedToFileAt: null | number
}
```

界面状态由它推导，不落盘：

- `ok`：最近成功且无错误
- `stale`：距上次成功超过 7 天
- `empty`：没有任何备份
- `failed`：`lastError` 非空

错误文案：`NO_SPACE` →「手机存储空间不足，之前的备份都还在」；`WRITE_FAIL` →「备份没有保存成功，请重试」；`CLOUD_FAIL` →「云端同步失败，本机备份正常」。

## 三、UI 规格（参照设计稿）

### 1. 「我的」页

- 用户卡下方放**一张状态卡**，点击进入「数据与备份」页：
  - `ok`（绿）：「数据与备份」/ 上次备份时间和条数，右侧 ›
  - `stale`（黄）：「已 N 天没有备份」，右侧「立即备份」按钮
  - `empty`（灰）：「还没有备份」，右侧「创建备份」按钮
  - `failed`（红）：「上次备份没成功」+ 原因，右侧「重试」按钮
- 其余设置分组：**通用**（语言、主题）、**打卡**（一键打卡 + 今日状态、位置调试）、**关于**（检查更新、隐私协议）。
- 修正副标题错字「个人信息与保好」→「个人信息与偏好」；底部 Tab 加文字标签；内容底部留出 Tab 栏高度。
- 全局去掉「零泄露风险」等绝对化表述。

### 2. 「数据与备份」页（自上而下）

1. **状态头**：图标 + 标题 + 副文案；下方状态标签（本机 / 云端副本 / 已保存到文件）；异常或风险横幅；主按钮「立即备份」（`empty` 时为「创建第一份备份」，`failed` 时为「重试备份」；执行中显示进度条）。
2. **我的数据**：打卡 / 专注 / 行程三个数字。
3. **备份记录**：列表，每行时间、条数、大小、标签（自动 / 手动 / 恢复前 / 最完整）；点击进入详情弹层。空状态给出说明文案。
4. **保存与导入**：保存备份文件、从文件导入备份、导出为表格。
5. **设置**：自动备份开关、云端副本入口。
6. **危险操作**（最底部）：清空所有打卡记录。

横幅规则：
- `ok` 且既没开云端副本也没保存过文件 → 黄色提示「备份目前只在这台手机上」+「保存到文件」按钮。
- `stale` → 提示建议现在备份。
- `failed` + `NO_SPACE` → 红色提示 + 「保存到文件」。

### 3. 弹层

- **备份详情**：条数摘要 + 「恢复到这个版本」「保存这份到文件」「删除这份备份」（二次确认，再点一次才删）。
- **恢复**：见上文第 5 节；两步完成，最后一页有「撤销恢复」。
- **保存备份文件**：展示文件名、条数、大小；列出发送给微信 / 保存到手机文件 / 上传到网盘；底部提示文件未加密。
- **导入文件**：选择文件 → 展示文件信息和条数 → 继续进入恢复；无效文件显示错误并可重选。
- **清空确认**：居中弹窗，输入「清空」才可点；先自动备份再清空。

### 4. 反馈原则

- 自动备份失败：只改变状态卡颜色和文案，不弹窗。
- 手动备份失败：在页内显示原因和重试按钮。
- 成功用轻提示（toast），不打断。
- 文案一律中文口语化，不出现「加密 / 密钥 / KDF / MAC」等术语。
